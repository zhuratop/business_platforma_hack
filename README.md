# Система анализа изменений СПР

Локальное многопользовательское приложение: React/TypeScript/Vite → FastAPI → SQLite WAL → отдельный Python worker → неизменяемый DuckDB на каждый прогон. Python-адаптер СПР отделён от универсального ядра. Проверенное окружение: Python **3.11**, Node.js **22**, Windows PowerShell (Linux также поддержан ядром). Версии зависимостей закреплены; для Python 3.12+ обновите SciPy и повторите проверки.

## Установка

В PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

## Запуск

Первый терминал:

```powershell
.\.venv\Scripts\python -m backend.app.workers.main
```

Второй терминал:

```powershell
.\.venv\Scripts\python -m uvicorn backend.app.api:app --host 127.0.0.1 --port 8000
```

Открыть **http://127.0.0.1:8000**. API обслуживает собранный интерфейс; запускать его после сборки. Два пользователя: **alice / demo**, **bob / demo**. Для одновременной демонстрации используйте два разных профиля браузера или обычное и приватное окно. Вкладки одного профиля разделяют cookie.

После установки также доступен запуск одной командой `./scripts/run.ps1`: API в текущем терминале, worker в скрытом процессе, его журналы — `runtime/worker.*.log`. Остановка во время расчёта прерывает задачу; после перезапуска worker она станет FAILED, затем создайте новый запуск.

При разработке: в третьем терминале `cd frontend; npm run dev`, интерфейс на `http://127.0.0.1:5173`, API проксируется на 8000. Бизнес-данные не отправляются внешним сервисам.

Настройки окружения (задавать одинаково для API и worker до запуска):

```powershell
$env:SPR_DATA_ROOT = 'C:\Users\User\Desktop\платформа данные\ЗАДАНИЕ'
$env:SPR_RUNTIME = "$PWD\runtime"
$env:PUBLIC_BASE_URL = 'http://127.0.0.1:8000'
$env:SPR_JOB_TIMEOUT = '600'
```

По умолчанию используется соседний с `Проекты` каталог `платформа данные\ЗАДАНИЕ`. `SPR_DATA_ROOT` — единственный разрешённый корень регистрации серверных датасетов. `SPR_DEMO_PASSWORD` задаёт пароль только при первичном создании пользователей. Runtime содержит конфигурации, снимки входов и кода, очередь, события, DuckDB и версии HTML; не удаляйте его при работающих процессах.

## Демонстрация без консоли

1. Войти как alice. «Датасеты» → «Импортировать каталог» с предложенным путём `data/RUN-20260827-0001`. Либо загрузить ZIP с одним `manifest.json` и указанными в нём срезами. JSON, количество и парность проверяются до запуска; входы копируются с SHA-256.
2. «Конфигурация» → выбрать датасет, обработчики и пять проверок; параметры доступны как JSON. Ключ оффера — `product_id + type`, вектор — индекс. Список исключений и бакеты редактируются здесь. «Сохранить и запустить» создаёт новый `run_id` со снимком кода.
3. «Журнал» показывает этапы и прогресс. «Код» открывает именно исполнявшийся снимок с hash; кнопка редактора открывает текущую версию. UI и работа bob доступны во время расчёта.
4. После READY открыть «Обзор изменений»: заявления, продукты и офферы имеют разные единицы и знаменатели. Итоговые числа вычисляются из входов, в приложении нет констант контрольного набора.
5. «Сводная» автоматически открывает отчёт по образцу задания: иерархия атрибута/значения × DIFF_FLAG × BEFORE/AFTER, изменения выделены оранжевым. Представления: ключевые атрибуты стратегии, итоговое решение, матрица переходов и «Своя раскладка». Выбор своей раскладки открывает настройки и сохраняет текущие параметры; можно очистить строки/колонки или фильтры, добавить измерения и нажать «Перестроить». Значения DIFF_FLAG и DECISION_CHANGED числовые. Страницы содержат по 100 логических строк; итоги относятся ко всей выборке и считают уникальные APP_ID. Число в ячейке или итоге → полный список APP_ID → заявка → подсвеченные атрибуты. Складывать разные ячейки как заявки нельзя. [Описание и скриншот](docs/PIVOT_REPORT.md).
6. «Автопроверки» — единая таблица неизменённых CHECK. Столбцы «Порог, %» и «Разница в %» показывают проценты с одним знаком после запятой; без процентного порога — прочерк. По проверке, аргументу и срезу доступны текстовые фильтры. Результат выбирается из «Все / PASS / FAIL», уверенность — «Все / HIGH / LOW». У порога и разницы отдельные поля «От» и «До» с включёнными границами; пустая граница не ограничивает диапазон, одинаковые границы выбирают точное значение. Принимаются точка и десятичная запятая. «Без порога» находит строки без численного порога. Все фильтры работают одновременно; общий сброс очищает их. Для CNT/TOTAL и заявок фильтров нет. LOW подсвечен мягко. Ограниченные APP_IDS явно подписаны; полный переход обеспечивает сводная.
7. «Написать свою проверку» → готовый редактируемый шаблон → «Проверить на паре» → «Выбрать в конфигурации» → отметить новую проверку → сохранить → «Автопроверки» → «Применить набор из конфигурации». Пересчитываются только проверки, DuckDB не меняется, прежний отчёт доступен до успешной атомарной публикации новой версии. Ошибка новой проверки сохраняет старую версию.
8. Для `.py`: в рабочей области выбрать тип процедуры и «Загрузить .py» либо источник «Размещённый .py файл» с разрешённым путём. Файлы допускаются в `scripts`, `runtime/scripts`, `SPR_DATA_ROOT/checks`. Сохранить и выбрать процедуру в конфигурации. Изменения normalizer/compare/facts применяются полным новым запуском. Пробный запуск показывает stdout, traceback и первые строки на реальной учебной паре из samples.
9. «Статистика и решение» → парные интервалы, точный Мак-Немар и Holm, сравнение продуктов/партнёров и анализ сопоставимости. Блок оценки готовности стратегии скрыт. Риск/лимиты/деньги недоступны без допданных. «HTML-отчёт» скачивает автономный оформленный документ с этими метриками и полной таблицей «Стратегия · ключевые атрибуты» для всего прогона, без ограничений страниц. Локальные фильтры и своя раскладка в выгрузку не переносятся. Встроены стили, навигация и оформление для печати; абсолютная ссылка открывает интерактивную сводную после входа владельца. Новый формат доступен и для ранее завершённых прогонов без пересчёта данных.

Перезагрузка страницы восстанавливает текущий run и вкладку из URL. У bob свои датасеты/скрипты/конфигурации/прогоны, ссылки alice возвращают 404.

## Проверки

```powershell
.\.venv\Scripts\python -m pytest backend/tests -q
.\.venv\Scripts\python -m scripts.demo_run
```

Первая команда проверяет учебный пример, типы/отсутствие, массивы и вектор, импорт, SQL/MartAPI, полные memberships сводной, две учётные записи, код/файл, новую проверку, неизменность кода CHECK и атомарные версии. Вторая обрабатывает весь открытый набор и проверяет контрольные числа. Выполнять `demo_run` при остановленном worker (он исполняет расчёт непосредственно для воспроизводимой проверки).

Браузерный тест (API и worker должны работать; на Windows нужен установленный Edge):

```powershell
Set-Location frontend
npx playwright test
Set-Location ..
```

Он проходит импорт полного набора через UI, конфигурацию и очередь, журнал/снимок кода, обзор, сводную и атрибут, изменение раскладки, новую проверку из редактора, HTML, восстановление и изоляцию bob во время расчёта. Результаты и скриншоты — `runtime`. В Linux поменяйте `channel` в `playwright.config.ts` на установленный браузер.

`performance.spec.ts` измеряет видимые задержки на полном прогоне, записанном предыдущим demo-тестом. Отдельно: `npx playwright test demo.spec.ts`, затем `npx playwright test performance.spec.ts`. HTTP-замеры: `python -m scripts.benchmark`; сравнительный замер старого и нового импорта: `python -m scripts.benchmark_import` (создаёт две копии в runtime, SHA-256 сверяется).

После браузерного демо `python -m scripts.verify_ready` повторно сверяет все контрольные числа готового прогона, 25 ответов с повтором продукта у разных типов оффера и наличие hit=null. Не запускает новый расчёт.

## Контракты и архитектура

На странице «Статистика и решение» продукты и партнёры подписаны названиями из данных прогона; при отсутствии названия показан ID с пояснением. В карточках одобрений/вероятности и таблицах продуктов/партнёров база BEFORE/AFTER показана в процентах, изменение AFTER − BEFORE и его CI — в процентных пунктах («п.п.»). Например: 50% → 40% означает −10 п.п. Уровень доверия CI (95%) остаётся в процентах. HTML использует те же единицы. «Целевая модель не менялась» скрыта также в HTML. Количество продуктов остаётся в продуктах на заявку. Медиана скрыта. Числа округлены максимум до четырёх знаков после запятой, малые p-value сохраняются в научной записи. Короткая проверка: `.\.venv\Scripts\python -m pytest backend/tests/test_stat_display.py backend/tests/test_report.py -q`; из `frontend`: `npx playwright test tests/statistics.spec.ts tests/html-export.spec.ts`.

- [API и общие типы](docs/API.md); Python DTO — `backend/app/domain/contracts.py`, TypeScript DTO — `frontend/src/types.ts`.
- `core/normalize.py` не знает полей СПР: массивы, пути, бакеты и исключения передаются параметрами. `scripts/default_spr` содержит доменный разбор и слой разрезов, `scripts/educational.py` — отдельный адаптер другого учебного формата.
- Вертикальный `normalized_union` хранит SOURCE и VALUE_KIND. Сравнение по `(APP_ID, PATH, ARRAY_KEY)` сохраняет типы, присутствие и четыре CHANGE_TYPE. Изменения считаются по VALUE, не по бакету.
- SQLite хранит метаданные/очередь/журнал в WAL, synchronous=NORMAL; worker атомарно забирает задачу и выполняет её в отдельном процессе с heartbeat и тайм-аутом. Повторный worker блокируется lock-файлом; незавершённые задания после перезапуска становятся FAILED. При аварии ОС последняя транзакция в NORMAL может быть потеряна; готовый файл и атомарная публикация не смешивают частичный отчёт с полным.
- Единственный writer закрывает `mart.tmp.duckdb`, проверки/статистика читают его read-only. После закрытия соединений файл переименовывается, публикуется HTML и READY. Готовая витрина неизменяема.
- `pivot_facts.CNT` соответствует полным уникальным APP_IDS, развёрнутым в fact_memberships. Укрупнение использует COUNT DISTINCT по memberships. Составной ключ оффера не схлопывает standard/manual. Связь продукта/партнёра определяется адаптером; исходные факты не размножаются при хранении.
- В сводной поля сгруппированы: основные, бизнес-разрезы и технические. DIFF_FLAG и DECISION_CHANGED предлагаются в фильтрах. ADJUSTED_BEFORE / ADJUSTED_AFTER показывают пару бакетов одной заявки; для матрицы переходов выберите один PATH. Пустой бакет может означать отсутствующее поле: различайте его по CHANGE_TYPE и деталям.
- При выборе продукта/партнёра общие атрибуты заявки доступны для всех участвовавших в паре продуктов/партнёров, включая исчезнувший в одном срезе продукт. Продуктовые атрибуты остаются у своего продукта и партнёра соответствующего среза. Укрупнение считает уникальные APP_ID, не сумму продуктовых связей. Это вычисляется при чтении; старые READY-прогоны работают без перезаписи DuckDB.
- Статистика: единица APP_ID, percentile bootstrap B=5000, seed=20260827, alpha=0.05, точный биномиальный Мак-Немар, Holm в заранее заданных семействах продуктов и партнёров. Смена модели/внешнего скора выделена. Целевой скор сравнивается только на одной модели/шкале, усреднение сначала по APP_ID.

## Ограничения

Прототип рассчитан на доверенный Python-код команды; отдельный процесс и тайм-аут не являются песочницей от вредоносного кода. Демо-авторизация предназначена для локального запуска; перед публичным размещением нужны OIDC, TLS, квоты и изоляция исполнителя. ZIP ограничен 1 ГиБ/50 000 JSON; новая сводная листается по логическим строкам (до 128 комбинаций колонок). Для старых API-запросов без page_size сохраняется лимит 5000 ячеек. Общие списки API постраничны; интерфейс показывает последние 100 объектов.

Финансовый файл, сценарные деньги, интеграция LLM и раннее поступление пар не реализованы: это A4 после обязательного приложения. Без допданных PD_default, offered_limit и денежные показатели имеют `unavailable`. `scoring.pd` — только APPROVAL_PROBABILITY. Нет эталона организаторов для числа любых различий; фактическое число выводится отдельно.

Расхождения учебных материалов учтены: `example/` — 12/14/26/14 строк и 6 изменений; старый `examples/` тоже содержит 6, хотя README говорит о 5. Первичные контракты docs имеют приоритет. Справочники по умолчанию сохранены в анализе.

Фактические результаты и производительность: [docs/VERIFICATION.md](docs/VERIFICATION.md).
