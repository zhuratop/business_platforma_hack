# Обновление сводной

Дальнейшее развитие экрана по примеру из задания описано в [PIVOT_REPORT.md](PIVOT_REPORT.md): многоуровневая шапка, иерархические строки, готовые представления, страницы и точные итоги.

Основные измерения: PATH, SOURCE, CHANGE_TYPE, VALUE_ADJUSTED и новые ADJUSTED_BEFORE / ADJUSTED_AFTER.
Бизнес-разрезы: продукт, партнёр, решения до/после, явно подписанные наборы типов партнёров/маршрутов заявки.
PREFIX, CLASS, SUFFIX, KEY, ARRAY_KEY находятся в группе «Технические».
DIFF_FLAG и DECISION_CHANGED предлагаются в фильтрах; API сохраняет возможность группировки по ним для совместимости.

Исправлено выпадение общих атрибутов при выборе продукта. Для общих атрибутов принадлежность продукту/партнёру определяется по всей паре, включая появление/исчезновение продуктовой попытки в одном срезе. При совместном фильтре продукт и партнёр должны принадлежать одной связи, а не разным продуктам заявки. Атрибут внутри продуктовой попытки сохраняет собственную привязку среза. Уникальный APP_ID учитывается один раз в ячейке при любом количестве связей и атрибутов.

Бакеты до/после разрешаются по APP_ID/PATH/ARRAY_KEY из comparison_mart, а не берутся из одного агрегированного факта. Это важно, когда несколько заявок имеют одинаковый бакет AFTER, но разные бакеты BEFORE. Ячейки, полный список заявок и подсветка атрибутов используют одну и ту же SQL-связь.

Схема хранимого pivot_facts и обязательный контракт CHECK не изменились. Существующие неизменяемые READY-файлы работают без пересчёта и миграции. Для анализа переходов бакетов рекомендуется фильтр по одному PATH; отсутствие поля по-прежнему различается через CHANGE_TYPE и признаки присутствия в деталях.

Проверено:

- 28 серверных тестов прошли: прежние 24 и 4 новых регрессионных теста сводной. В новых тестах есть исчезнувший продукт, два продукта и разных партнёра одной заявки, ложная комбинация продукта/партнёра, заявка без продукта, общий AFTER-факт с разными BEFORE-бакетами, пагинация и подсветка.
- Два браузерных теста в Edge прошли: сгруппированные измерения, доступность признаков в фильтрах, новая матрица бакетов, продуктовый фильтр и переход до атрибута; проверены также видимые задержки.
- На прежнем полном прогоне для product_id=15210 и PATH=decisionResult.decision получено 927 уникальных заявок в каждом SOURCE; со сменой решения — 177 в каждом SOURCE. Постраничный обход совпадает с количеством в ячейке.
