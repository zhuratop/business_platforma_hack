# Все атрибуты · дерево JSON

Откройте **«Сводная таблица»**: дерево всех атрибутов появляется сразу. Это единственный вариант страницы; выбор типа таблицы, прежние раскладки и их настройки из интерфейса убраны. Фильтры среза и DIFF_FLAG, раскрытие и переходы к заявкам сохранены. Обновить дерево можно кнопкой обновления в шапке приложения.

Дерево строится по всем строкам сохранённого `normalized_union`, соединённым с `comparison_mart` по APP_ID/PATH/ARRAY_KEY. Это данные нормализации; исключённые конфигурацией технические поля и не создающие листовых строк пустые контейнеры не восстанавливаются из исходных файлов. DuckDB и исходные JSON не меняются.

Раскрытие идёт по сегментам PATH, затем по полным ARRAY_KEY, затем по типизированным значениям/бакетам. Офферы с одинаковым product_id и разными type остаются разными узлами составного ключа. У scalar/object-пути, форма которого отличается у разных заявок/срезов, показываются и дочерние поля, и «Значения этого атрибута». null, boolean, числа и строки различаются; пустая строка показана как `""`, строка NULL — как `"NULL"`, JSON-null — `null`.

Нажатие стрелки раскрывает узел. Сворачивание родителя скрывает и сворачивает все вложенные раскрытые узлы. «Свернуть всё» закрывает дерево целиком. Потомки запрашиваются только по мере раскрытия; уровни с большим количеством значений подгружаются по 50 кнопкой «Показать ещё узлы», без общего ограничения в 5000 ячеек.

Два фильтра применяются сразу и сбрасывают раскрытие/кеш:

Когда выбраны все значения DIFF_FLAG, каждый видимый срез BEFORE/AFTER делится на две колонки: DIFF_FLAG = 0 и DIFF_FLAG = 1. При выборе одного флага остаётся по одной колонке на срез. Новые ячейки API называются BEFORE_0, BEFORE_1, AFTER_0, AFTER_1; прежние BEFORE, AFTER, TOTAL сохранены для совместимости. Токен каждой новой ячейки фиксирует SOURCE и DIFF_FLAG, включая переход и подсветку. Такое же разбиение всегда включено в полный HTML-отчёт. Родительский узел может учитывать одну заявку в обеих группах по разным атрибутам, поэтому итог считается отдельным COUNT DISTINCT, а не суммой флагов.

- Срез: оба / BEFORE (MASTER) / AFTER (BETA).
- DIFF_FLAG: все / 0 — без изменений / 1 — есть изменения.

Колонки показывают число уникальных APP_ID в BEFORE, AFTER и их объединении. При выборе одного среза в таблице остаётся только этот срез и уникальный итог. Свёрнутый родитель продолжает считать все подходящие дочерние атрибуты; его число не является суммой потомков. Источник, узлы и значения также неаддитивны из-за нескольких атрибутов/продуктов одной заявки. Исчезнувший атрибут виден в BEFORE с DIFF_FLAG=1, новый — в AFTER. Изменение внутри одного бакета сохраняет DIFF_FLAG=1.

Любое ненулевое число открывает полный список APP_ID через существующую пагинацию. Далее заявка показывает только соответствующую подсветку атрибутов, включая тип/значение/ARRAY_KEY и выбранный срез. Серверные cell_token подписаны и привязаны к run_id; доступ только у владельца READY-прогона.

API: `POST /api/runs/{id}/pivot/tree`, тело `{path:"",stage:"path",array_key:null,filters:{},page:1,page_size:50}`. stage: `path`, `keys`, `values`. Фильтры только SOURCE и DIFF_FLAG. Ответ содержит `nodes`, `totals`, `pagination`; каждый узел имеет метаданные следующего запроса, счётчики и подписанные токены. Переход и подсветка используют прежние `/pivot/apps` и `/apps/{app_id}` с токеном дерева. Есть загрузка/ошибка/повтор для каждого уровня и пустое состояние.

Короткие проверки: `pytest backend/tests/test_attribute_tree.py -q`; из frontend: `npx playwright test tests/attribute-tree.spec.ts tests/overview-navigation.spec.ts`.
