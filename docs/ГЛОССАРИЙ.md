# Глоссарий

Термины предметной области. Читать целиком не обязательно — держите под рукой.

## Про решения по заявкам

| Термин | Значение |
|---|---|
| **СПР** | Система принятия решений. Сервис, который по заявке возвращает решение, подбирает продукт и формирует предложение клиенту |
| **Стратегия** | Логика внутри СПР: правила, скоринговые модели, пороги. Это то, что меняют, и то, что вы помогаете тестировать |
| **Заявка** | Обращение клиента за продуктом. В датасете идентифицируется `application_id`, он же `APP_ID` |
| **Решение** | `APPROVE` — одобрить, `REJECT` — отказать. В более полных системах бывает ещё `VERIFICATION` — отправить на проверку |
| **Оффер** | Предложение клиенту: конкретный продукт с тарифом и условиями |
| **AR (Approval Rate)** | Доля одобренных заявок. Основной показатель влияния изменения стратегии |

## Про правила

| Термин | Значение |
|---|---|
| **Стоп-фактор** | Правило, срабатывание которого ведёт к отказу. Например `AGELOW@21` — клиент младше 21 года |
| **`hit`** | Признак срабатывания правила: `true` — сработало, `false` — не сработало, `null` — не вычислялось |
| **`rejectReason`** | Класс причины отказа: `HARDCHECK` — сработало правило, `CUTOFF` — не прошёл порог по скору |
| **`rejectReasonCode`** | Конкретная причина: имя правила либо имя порога |
| **Hard-check** | Жёсткая проверка, которая отсекает заявку независимо от скора |

## Про скоринг

| Термин | Значение |
|---|---|
| **Скоркарта / модель** | Модель, возвращающая балл или вероятность по клиенту |
| **Предиктор (`features`)** | Переменная на входе модели. Предиктором может быть и готовый скор от внешнего источника |
| **Готовый скор** | Балл, полученный от внешнего источника (например бюро кредитных историй) без расчёта на своей стороне |
| **Целевой скор (`pd`)** | Скорбалл, выбранный стратегией для принятия решения по конкретному продукту, из числа посчитанных моделей |
| **`cutOff`** | Порог отсечения: если скор его не проходит — отказ. У разных продуктов и сегментов пороги разные |
| **Бэнд** | Диапазон значений, по которому выбирается порог или ставка. Например: скор ≥700 → один порог, 600–699 → другой |
| **Три этапа скоринга** | 1) готовые скоры извне; 2) расчёт моделей на предикторах; 3) раскладка полученных баллов по продуктам вместе с порогами. Одно и то же число закономерно встречается на нескольких этапах — см. `02_ФОРМАТ_ДАННЫХ.md` |

## Про тестирование изменений

| Термин | Значение |
|---|---|
| **Прогон** | Один запуск набора заявок через две версии стратегии. Имеет идентификатор, в датасете это `RUN-20260827-0001` |
| **Срез** | Результаты одной версии стратегии. Их два: BEFORE и AFTER |
| **BEFORE (MASTER)** | Текущая версия — то, что на проде. Эталон, с которым сравнивают |
| **AFTER (BETA)** | Новая версия с проверяемым изменением |
| **Нормализация** | Приведение ответа к плоской таблице «одна строка = один атрибут одной заявки» |
| **Бакетизация** | Приведение значения к интервалу или категории, чтобы группировать близкие значения в отчёте. `117325` → `(100K – 250K]` |
| **`VALUE` / `ADJUSTED_VALUE`** | Исходное значение атрибута и оно же после бакетизации |
| **`DIFF_FLAG`** | Признак различия атрибута между срезами: 1 — изменился, 0 — нет |
| **`CHANGE_TYPE`** | Как именно изменился: `VALUE_CHANGED`, `ATTRIBUTE_NEW`, `ATTRIBUTE_LOST`, `SAME` |
| **Витрина** | Плоская таблица результатов сравнения, по которой строится отчёт. Схема задана в `СХЕМА_ВИТРИНЫ.md` |
| **Разрезы (сегменты)** | Атрибуты заявки, по которым аналитик фильтрует отчёт: продукт, тип партнёра, решение |
| **Сводная таблица (pivot)** | Таблица с изменяемой раскладкой: поля можно переставлять между строками, колонками и фильтрами |
| **Drill-down** | Переход от агрегата к деталям: из числа в сводной — к списку заявок, из заявки — к её атрибутам |
| **Автопроверка** | Формализованное ожидание вида «этот показатель не должен измениться больше чем на X» с вердиктом PASS/FAIL |

## Про данные датасета

| Термин | Значение |
|---|---|
| **МФО** | Микрофинансовая организация. В датасете партнёры, чьи продукты подбираются клиенту |
| **`product_trials`** | Прогон заявки по каждому продукту отдельно: свои правила, свои скоры, свой порог, своё решение |
| **`available_offers`** | Итоговая выдача клиенту: продукты с позициями `rank` |
| **`type: manual`** | Оффер, добавленный ручной стратегией, а не обычным подбором |
| **`ext_data`** | Сырые ответы внешних источников, как они пришли |
| **`characteristics`** | Разобранные значения от внешних источников в плоском виде |
